## 3. 제안

1. **범용 목록 파서 하나 + 사이트별 목록 주소 설정**
   - 이번 점검에 쓴 방식("날짜가 가까이 붙은 링크 = 글 행")으로 그누보드·자체 구조·대화·팔달·SK청솔 같은 서버 렌더링 게시판을 한 파서로 읽는다
   - anyboard는 은평용 코드를 일반화, JSON API(동탄)만 전용 파서
   - 사이트마다 필요한 건 `목록 주소`(+ 필요하면 인증서 예외)뿐 → `docs/gyeonggi/gyeonggi_centers.yaml`
   - 이 파서로 서울 복지관 7곳도 옮기면 출처 목록 통합(구조 점검 1번)과 함께 정리된다
2. **앱 쪽을 먼저 정해야 함** (수집보다 앞)
   - 지금 앱의 지역은 서울 구 단위 칩·체크 목록(이미 13개). 경기 31개 시·군을 붙이면 **시·도 → 시·군·구 2단계 선택**이 필요
   - 서버는 경기 공고를 `all` 토픽에도 보내므로, 지역을 고르지 않은 서울 사용자에게도 경기 알림이 간다 → `all`의 의미(서울 전체? 전국?)를 정해야 함
3. **1차 범위 제안** (4장 전체 점검 반영): 범용 파서·그누보드·`bid` 세 방식으로 읽히는 41곳(ok)부터. 전용 파서가 필요한 동탄·기흥·부천은 2차
4. ~~목록 확보~~ → 완료 (2026-11-18, 사용자가 협회 페이지 저장)
5. **시니어클럽**: 행정 글이 62%지만 노인일자리 참여자 모집(11~12월)이 있어 넣을 가치가 있다. 규칙 필터가 행정 글을 걸러 내므로 AI 부담은 작다

- **시니어클럽은 행정 글이 대부분**: 규칙 제외 62% (업무추진비·예산·입찰·사업추진현황 공개). 쓸모 있는 글은 연 1~2회의 **「2027년 노인일자리 및 사회활동지원사업 참여자 모집」**(지금 철 — 안성맞춤·의왕·김포가 11월에 이미 올림). 건수는 적어도 어르신에게 가장 중요한 공고
- **시·군 범위**: 읽히는 기관이 하나라도 있는 곳 **22/31**. 없는 곳: 시흥·안산·광명·군포·안양·동두천·과천·구리·연천 (차단·접속 오류·게시판 못 찾음)

- **추가 확인 33곳의 사정**: 게시판 못 찾음 22(메뉴가 스크립트·이미지), 찾은 게시판이 '복지관 소식'이라 공지인지 확인 6, 접속 오류 5(시간 초과·리디렉션 반복·인증서). 차단 9곳은 우회하지 않는다
- 점검 한계: 게시판마다 첫 쪽만 봤고, '공지' 이름이 붙은 게시판을 우선 골랐다. 수집에 붙이기 전 사이트별로 목록 주소를 사람이 한 번 확인할 것

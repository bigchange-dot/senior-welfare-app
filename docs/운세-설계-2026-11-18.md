## 1. 한눈에

```
[한 번]  문장 묶음 초안 → 사용자 검토 → backend/fortune_phrases.yaml
[매일 07:00] fortune_function (클라우드 예약 함수, AI·맥 안 씀)
    → 오늘·내일 운세 계산 (년주 60가지) → Firestore fortunes/{날짜}
    → 토픽 `fortune` 하나로 알림 1건: "오늘의 띠" 2~3개 년생 핵심어
[앱]  알림 탭 → 운세 화면 (처음 한 번 띠 → 년생 선택, 기기에 기억)
    → [다른 띠 보기]·[오늘 새 공고] 누를 때 전면광고 (빈도 제한 그대로)
```

- **운세는 맥과 상관없이 돈다.** 문장은 미리 만들어 둔 묶음에서 고르기만 하므로 AI를 부르지 않는다.
- **출생연도는 기기 밖으로 나가지 않는다.** 알림은 모두에게 같은 내용이고, 내 운세는 앱이 문서에서 골라 보여 준다.

## 2. 운세 계산

### 2.1 간지

| 항목 | 계산 | 검증값 |
|---|---|---|
| 오늘 일진 | `(날짜 − 2000-01-01 일수 + 54) mod 60` | 2000-01-01 무오, 1900-01-01 갑술, 2026-11-18 병신 |
| 년주 | `(출생연도 − 4) mod 60` | 1984 갑자, 2026 병오, 1956 병신 |
| 60갑자 인덱스 | 천간 = `i mod 10` (갑을병정무기경신임계), 지지 = `i mod 12` (자축인묘진사오미신유술해) | |

- 날짜는 한국 시간 기준. 시주·자시 경계는 쓰지 않는다.
- 띠 경계(입춘·설)는 계산하지 않는다. 사용자가 띠를 직접 고르기 때문이다 (4.1).

### 2.2 판정

내 년간과 오늘 일간의 **십신**, 내 년지와 오늘 일지의 **관계**를 본다.

- 십신(10): 오행·음양으로 정한다. 같은 오행이면 비견·겁재, 내가 생하면 식신·상관, 내가 극하면 편재·정재, 나를 극하면 편관·정관, 나를 생하면 편인·정인. 음양이 같으면 앞쪽, 다르면 뒤쪽이다.
- 관계(3): 육합(자축·인해·묘술·진유·사신·오미)이면 **합**, 충(자오·축미·인신·묘유·진술·사해)이면 **충**, 나머지는 **평**.

등급(3)은 늘 좋은 쪽으로 기울게 잡는다. 충인 날만 '차분히'가 되고, 12일 중 하루꼴이다.

| 조건 | 등급 | 표시 |
|---|---|---|
| 합 | 좋음 | ☀️ 좋은 날 |
| 평 + 정재·정관·정인·식신 | 좋음 | ☀️ 좋은 날 |
| 평 + 나머지 십신 | 보통 | ⛅ 무난한 날 |
| 충 | 차분히 | 🌤 천천히 가는 날 |

십신별 총운 주제 (문장 쓸 때 기준):

| 십신 | 주제 |
|---|---|
| 비견 | 친구·형제, 함께하는 일 |
| 겁재 | 나눔, 씀씀이 살피기 |
| 식신 | 먹을 복, 건강, 여유 |
| 상관 | 말솜씨, 재주 드러내기 |
| 편재 | 뜻밖의 재물, 나들이 |
| 정재 | 알뜰한 살림, 꾸준한 재물 |
| 편관 | 바쁜 하루, 맡은 일 |
| 정관 | 인정받음, 차례·질서 |
| 편인 | 배움, 취미, 생각 정리 |
| 정인 | 도움 받음, 자녀·어른의 정, 문서 |

### 2.3 문장 고르기

- 총운: 십신 × 관계 = 30갈래에서 하나를 고른다.
- 건강·가족·재물: 등급 × 분야에서 하나씩 고른다.
- 고르는 방법: `sha256("{날짜}|{년주}|{칸}")`을 문장 수로 나눈 나머지. 같은 날, 같은 년주면 언제 계산해도 같은 결과가 나온다. 파이썬 `hash()`는 실행할 때마다 값이 달라서 쓰지 않는다.
- 행운의 색·숫자: 같은 방법으로 오행 다섯 가지 중 하나를 골라 매일 바뀌게 한다.
  목 초록 3·8 / 화 빨강 2·7 / 토 노랑 5·10 / 금 흰색 4·9 / 수 남색 1·6

## 3. 문장 묶음 (`backend/fortune_phrases.yaml`)

```yaml
headlines:              # 총운 — 십신 × 관계. 문장 + 알림용 핵심어
  정재:
    평: [{text: "꾸준히 모은 것이 빛을 보는 날이에요.", keyword: "알뜰한 결실"}, ...]   # 12개
    합: [...]           # 6개
    충: [...]           # 6개
  ...
areas:                  # 등급 × 분야 — 10개씩
  좋음:   {건강: [...], 가족: [...], 재물: [...]}
  보통:   {...}
  차분히: {...}
```

- 양: 총운 240개(10십신 × (평 12 + 합 6 + 충 6)) + 분야 90개(3 × 3 × 10) = **약 330문장**. 평인 날이 12일 중 10일이라 평 문장을 더 많이 둔다.
- 만드는 법: 맥 Ollama나 Claude 세션으로 초안을 만들고, 사용자가 한 번 검토한 뒤 커밋한다. 매일 AI를 부르지 않는다.
- 말투:
  - "~해요"체, 한 문장 40자 이내, 핵심어는 6자 이내로 쓴다.
  - 충인 날도 권유로 쓴다. 예: "서두르지 말고 천천히 하면 좋은 날"
  - 금지어(테스트로 검사): 사고, 사망, 죽, 병원, 수술, 질병, 손실, 손해, 파산, 이별, 다툼, 소송, 도난, 불운, 흉, 재앙, 위험
- 화면 아래에 늘 **"재미로 보는 운세입니다"** 를 표시한다.

## 4. 앱

### 4.1 띠·년생 선택

- 처음 운세 화면에 들어오면 **띠(그림 12개) → 년생**을 고른다. 고른 값은 기기(`shared_preferences`)에만 저장하고, 다음부터는 바로 내 운세를 보여 준다.
- 년생 목록은 1930~1989년(60갑자 한 바퀴, 띠마다 5개)이다.
- 띠를 먼저 고르게 하므로 1~2월생의 띠 경계 문제가 생기지 않는다.

### 4.2 운세 화면

```
오늘의 운세 · 11월 18일 (병신일)
🐵 56년생 원숭이띠                       [띠 바꾸기]
☀️ 좋은 날
뜻밖의 도움이 들어오는 날이에요. 혼자 애쓰지 마세요.
건강  아침 산책이 몸을 가볍게 해 줘요
가족  오랜만에 자녀에게 먼저 전화해 보세요
재물  작은 지출을 아끼면 마음이 편해요
행운의 색 노랑 · 숫자 5
[다른 띠 보기]        [오늘 새 공고 N건 보기]
재미로 보는 운세입니다
──────── 배너 광고 ────────
```

- 홈 위쪽에 운세 카드를 둔다. 띠를 안 골랐으면 "내 띠 운세 보기", 골랐으면 "☀️ 좋은 날 · 뜻밖의 도움"처럼 보여 준다. 누르면 운세 화면으로 간다.
- '다른 띠 보기'로 가족 띠를 볼 수 있다. 이때 내 띠 설정은 바뀌지 않는다.
- 오늘 문서가 없으면(발송 전 등) "오늘 운세를 준비하고 있어요"를 보여 준다. 함수가 내일 문서도 미리 쓰므로(5.1) 평소에는 생기지 않는다.

### 4.3 광고

| 위치 | 광고 | 비고 |
|---|---|---|
| 운세 화면 아래 | 배너 1개 고정 | '광고' 표시 |
| [다른 띠 보기]·[오늘 새 공고] 누를 때 | 전면광고 | `AdService.canShowInterstitial()` (세션 3회·3분 간격) 그대로. 운세 화면을 열 때 미리 로드 |
| 알림 탭 직후·앱 시작 | **넣지 않음** | AdMob이 앱 로드·종료 때의 전면광고를 금지함. 어르신 오클릭·이탈 위험 |
| 앱 오프닝 광고 | 지금은 안 씀 | 정책상 가능하지만, 알림 탭마다 뜨면 위와 같은 문제 |

- AdMob 규칙인 "사용자 동작 두 번에 전면광고 최대 1회"를 지킨다. 알림 탭(1) → 버튼(2) → 광고 순서다.
- 공고 웹뷰에서 뒤로 갈 때 나오는 기존 전면광고는 그대로 둔다. 운세에서 공고로 이어지면 그 기회도 늘어난다.
- 근거: [AdMob 금지된 전면광고 구현](https://support.google.com/admob/answer/6201362), [앱 오프닝 광고 가이드](https://support.google.com/admob/answer/9341964)

### 4.4 알림 설정

- 운세 알림은 공고 알림과 **따로** 켜고 끈다. 설정 화면에 스위치를 둔다.
- 공고 '알림 끄기'가 운세를 끄지 않고, 운세를 꺼도 공고 알림은 그대로다.
- `FcmService.syncSubscriptions()`의 `wanted`에 운세 설정(`fortune`)을 더한다. 지금은 공고 알림이 꺼져 있으면 `unsubscribeAll()`로 모두 해지하므로, 운세만 남기도록 분기를 고친다.

**처음 켜기: 묻고 켠다** (사용자 결정 2026-11-18). 기본값은 꺼짐이다.

```
(띠·년생을 처음 고르고 첫 운세를 본 뒤, 운세 아래)
내일 아침 7시에도 운세를 알려 드릴까요?
[네, 받을게요]   [괜찮아요]
```

- 운세를 먼저 보여 주고 묻는다. 무엇을 받는지 알고 고르게 하기 위해서다. 홈 운세 카드("내 띠 운세 보기")가 이 화면으로 이어진다.
- 한 번만 묻는다. 답은 `fortune_notif`(켜짐 여부)와 `fortune_notif_asked`로 저장한다. 그 뒤에는 설정 화면 스위치로만 바꾼다.
- [네]를 눌렀는데 휴대폰 알림 권한(안드로이드 13+)이 없으면 그때 권한을 요청한다. 거부하면 스위치는 꺼진 채로 두고 "휴대폰 설정에서 알림을 허용해 주세요"라고 안내한다.
- 기존 사용자와 새로 설치한 사용자 모두 같은 흐름이다. 업데이트했다고 저절로 켜지지 않는다.

### 4.5 측정 (Firebase Analytics)

사용자 결정(2026-11-18)으로 운세와 함께 넣는다. 수익화 검토 9번 "측정 불가"도 함께 해결된다.

| 이벤트 | 언제 | 파라미터 |
|---|---|---|
| `fortune_view` | 운세 화면이 열림 | `source`: `notification` / `home_card` / `settings` |
| `fortune_notif_answer` | 알림 받기 질문에 답함 | `answer`: `yes` / `no` / `no_permission` |
| `fortune_other_animal` | 다른 띠 보기 | 없음 |
| `fortune_to_notices` | 운세 화면 → 오늘 새 공고 | 없음 |
| `notice_open` | 공고를 엶 | `source`: `notification` / `list` / `bookmark` |

- **띠·년생은 이벤트에 넣지 않는다.** "기기에만" 원칙을 지킨다. 어떤 띠를 많이 보는지는 재지 않는다.
- 디버그 빌드는 수집을 끈다 (`setAnalyticsCollectionEnabled(!kDebugMode)`). 태블릿 시험이 숫자에 섞이지 않게 하기 위해서다.
- 광고 ID 수집은 끈다. 매니페스트에 `google_analytics_adid_collection_enabled=false`를 넣는다. AdMob은 원래대로 광고 ID를 쓴다.
- 볼 숫자:
  - 운세 알림 탭률: `fortune_view(source=notification)` ÷ 발송 수
  - 운세에서 공고로 넘어가는 비율: `fortune_to_notices` ÷ `fortune_view`
  - 질문 수락률: `fortune_notif_answer(answer=yes)` 비율
- 알림에도 `fcm_options.analytics_label="fortune"`을 붙여, Firebase 콘솔 FCM 보고서에서 운세 알림 발송·수신을 공고 알림과 나눠 본다.

## 5. 서버

### 5.1 `fortune_function` (`backend/main.py`)

```python
@scheduler_fn.on_schedule(schedule="0 7 * * *", timezone=options.Timezone("Asia/Seoul"),
                          region="asia-northeast3", memory=options.MemoryOption.MB_256)
```

1. 오늘·내일의 `fortunes/{YYYY-MM-DD}` 문서를 쓴다. 덮어써도 같은 결과다. 내일 것을 미리 쓰는 이유는 07:00 전에 앱을 연 사람도 오늘 운세를 볼 수 있게 하기 위해서다.
2. `system_status/fortune.last_push_date`가 오늘이 아니면 알림을 보내고 기록한다. 재시도해도 두 번 보내지 않는다.
3. AI 호출, 맥, Gemini 크레딧과 상관없다. 계산과 문장 고르기는 `backend/fortune.py`가 맡는다.

### 5.2 Firestore 문서

```
fortunes/2026-11-18
  date: "2026-11-18", iljin: "병신", day_animal: "원숭이"
  push: {title, body}
  entries: {"0": {level, headline, keyword, health, family, money, color, number}, ... "59"}
```

- 60항목, 약 30KB다. 앱은 하루에 이 문서 1개만 읽는다.
- `firestore.rules`에 `match /fortunes/{date} { allow read: if true; allow write: if false; }`를 추가한다.

### 5.3 알림

```
제목: 🐵 오늘은 원숭이띠 날 · 오늘의 운세
본문: 44년생 반가운 소식 · 56년생 뜻밖의 도움 · 68년생 차분히
```

- **오늘의 띠** = 오늘 일지의 띠다. 일진을 따라 12일마다 저절로 돈다.
- **년생 2~3개** = 그 띠의 해 중 출생연도가 (올해 − 91)~(올해 − 56)인 것이다. 36년 범위라 띠마다 정확히 3개가 나온다. 2026년 원숭이띠면 1944·1956·1968이다.
- 본문은 40자 이내로 쓴다. 글자를 크게 쓰는 폰에서는 접힌 알림에 한 줄만 보인다.
- 문구는 항상 좋은 쪽으로 쓴다. 잠금화면에 그대로 뜨고 가족도 볼 수 있다.
- FCM 설정:
  - 토픽 `fortune`, `data={type: "fortune", date}`
  - `android.priority="high"`, `ttl=12시간` — 다음 날 어제 운세가 도착하지 않게
  - `notification.channel_id="fortune"`, `tag="fortune"` — 안 읽은 어제 알림을 오늘 것으로 바꿔 쌓이지 않게
  - `fcm_options.analytics_label="fortune"` (4.5)
- 하루 1건만 보낸다. 안 열었다고 다시 보내지 않는다.

### 5.4 알림 채널 (`MainActivity.kt`)

- 지금 서버는 공고 알림을 `channel_id="welfare_alerts"`로 보내지만, 앱 어디에도 이 채널을 만드는 코드가 없다. 그래서 안드로이드 기본(기타) 채널로 들어가는 것으로 보인다. 실기기에서 확인할 것.
- 앱 시작 때 채널 두 개를 만든다. 새 패키지는 필요 없다.
  - `welfare_alerts` "복지 공고 알림" — 중요도 높음
  - `fortune` "오늘의 운세" — 중요도 보통 (소리 있음, 화면 위 팝업 없음)
- 그러면 휴대폰 설정에서 운세만 끌 수 있다. 운세가 귀찮아 앱 알림을 통째로 끄면 공고 알림까지 끊기는데, 이걸 막는다.

### 5.5 감시

- `system_status/fortune`에 마지막 실행·발송 날짜를 남긴다.
- 기존 `health_check_function`의 10:00 회차가 "오늘 운세 알림 미발송"을 함께 확인한다 (`monitoring.py`).

## 7. 테스트

- 백엔드 (`test_fortune.py`)
  - 기준값: 2000-01-01 무오, 1900-01-01 갑술, 2026-11-18 병신, 1984 갑자년, 2026 병오년
  - 십신 10가지, 육합·충 표
  - 오늘의 띠 → 년생 3개 (2026-11-18 → 1944·1956·1968)
  - 같은 날짜·년주면 같은 결과
  - 문장 묶음: 갈래마다 개수, 금지어 없음, 문장 40자·핵심어 6자 이내, 알림 본문 40자 이내
- 프론트
  - 띠·년생 선택 저장, 운세 카드·화면 글자 2배, 알림 `type: fortune` 경로
  - 알림 질문은 한 번만 나오는지, [괜찮아요]면 구독하지 않는지
  - Analytics 이벤트 파라미터에 띠·년생이 없는지
- 실기기 Analytics: Firebase 콘솔 DebugView로 이벤트 5가지 확인 (`adb shell setprop debug.firebase.analytics.app <패키지>`)
- 실기기: 꺼진 상태·백그라운드에서 알림 탭 → 운세 화면. 로컬 빌드는 FCM 토큰을 못 받으므로 **Play 내부 테스트 트랙**에서 확인한다.

## 9. 검토했다가 뺀 안

| 안 | 뺀 이유 |
|---|---|
| 생년월일 + 일주 + 음력 변환 (HANDOFF 초안) | 입력 부담이 크다. 변환 라이브러리(`korean-lunar-calendar`)가 파이썬이라 "생년월일은 기기에만" 원칙과 부딪힌다 |
| 출생연도 입력 + 토픽 60개로 사람마다 다른 알림 | 처음 입력 화면이 필요하고, 토픽 이름에 출생연도가 담긴다. 하루 한 띠 공통 알림으로 단순화 (사용자 결정 2026-11-18) |
| 매일 AI로 문장 생성 (Gemini·Ollama) | Gemini는 크레딧 소진, 맥은 09:01만 보장된다. 불안한 표현을 매일 검사해야 한다 |
| VM 서버 | 운세는 AI·맥이 필요 없어 해당 없음 |
| 알림 탭 직후 전면광고 | AdMob이 앱 로드 때 전면광고를 금지한다. 어르신 오클릭·이탈 위험 |
